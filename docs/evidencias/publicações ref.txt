Download em massa de notas fiscais de serviço

Desenvolvi um aplicativo para baixar em lote os XMLs de NFS-e, emitidas, recebidas e eventos, pela API pública nacional, utilizando os certificados digitais A1 das empresas atendidas.

Desenvolvido com Claude Code, em WinForms / .NET 8.

O problema
O processo anterior utilizava uma extensão de navegador. Ela atendia uma empresa por vez e, como o navegador apresentava um certificado por sessão, trocar de empresa exigia fechar e reabrir o navegador.
Para uma carteira com dezenas de empresas, o processo não escalava.

O que construí
Um aplicativo desktop capaz de percorrer toda a carteira em uma única execução.
Para cada empresa, o aplicativo utiliza seu respectivo certificado digital A1 para acessar a API, permitindo processar várias empresas sem precisar trocar manualmente o certificado ou reiniciar o navegador.
A comunicação com a API utiliza autenticação por certificado digital (mTLS).

Como funciona
A sincronização utiliza o NSU como cursor sequencial, persistido individualmente para cada empresa.

Assim, cada execução:
→ retoma de onde a anterior parou
→ consulta os documentos disponíveis
→ pagina até o fim da caixa
→ descompacta os XMLs
→ organiza os arquivos na estrutura de pastas já utilizada pela equipe fiscal

Dessa forma, os lotes antigos e os novos continuam convivendo na mesma árvore de diretórios, sem precisar alterar o processo que a equipe já utilizava.
O objetivo não foi apenas automatizar o download, mas eliminar uma limitação operacional que aparecia justamente quando o volume de empresas aumentava.

Emitir nota fiscal de serviço ainda consome horas de trabalho que poderiam estar em outro lugar.

No emissor nacional, cada NFS-e segue o mesmo roteiro: consultar a planilha, preencher os dados do tomador, informar o serviço, digitar valores e retenções, emitir, conferir, baixar o PDF e o XML e enviar ao cliente por e-mail.

Mesmo num cenário conservador, em que tudo funciona como deveria, com os dados organizados, o portal respondendo normalmente e nenhuma interrupção, o processo leva entre 3 e 5 minutos e cerca de 30 a 40 cliques por nota, além da digitação. Num lote de 15 notas, isso representa entre 45 minutos e uma hora de trabalho, de 450 a 600 cliques e muitas oportunidades para um erro de digitação virar cancelamento e retrabalho.

Foi para resolver esse problema que desenvolvi o Nota Rápida, um aplicativo para Windows que automatiza a emissão de NFS-e Nacional em lote.

Como funciona:

• O cadastro do cliente começa pelo CNPJ: os dados da empresa são preenchidos automaticamente.
• Cada tomador fica salvo com seus padrões de serviço, descrição, valor e retenções.
• Na emissão, basta escolher a competência, selecionar as notas e confirmar.
• O sistema valida, assina e transmite cada nota à NFS-e Nacional.
• Cada cliente recebe a sua nota por e-mail automaticamente, com o PDF e o XML anexados.

O resultado: um lote inteiro é emitido e entregue com cerca de 8 cliques e um minuto de atenção, seja ele de 5 ou de 50 notas.

O Nota Rápida já está em operação, emitindo notas reais, e foi validado e aprovado pelo cliente que o utiliza no dia a dia. A evolução é contínua: cada ciclo de uso gera ajustes e novas funcionalidades, sempre a partir da rotina de quem usa o produto.

Segurança e confiabilidade fazem parte do projeto desde o início:

• A chave privada do certificado digital permanece no repositório do Windows e nunca é exportada.
• Integração direta com a API oficial da NFS-e Nacional, com assinatura XMLDSig.
• Toda nota passa por 12 regras de validação fiscal antes do envio.
• A numeração é conferida na Sefin antes de cada transmissão, evitando duplicidade.
• Os dados ficam em banco local cifrado, com trilha de auditoria.

O aplicativo é construído com Tauri 2, React e TypeScript, com o motor fiscal em Python.

Se o seu escritório ou empresa ainda emite notas uma a uma, terei prazer em mostrar o Nota Rápida funcionando. E profissionais de tecnologia que queiram conversar sobre o projeto também são bem-vindos.

✅ Baixa de XMLs em massa (emitidas e recebidas);

✅ Download em arquivo ZIP;

✅ Geração automática dos DANFSe (PDF);

✅ Relatório completo das notas consultadas;

✅ Processo incremental através do controle de NSU.

📌 Sobre o “Último NSU Baixado”

O NSU (Número Sequencial Único) funciona como um identificador de controle dos documentos já processados. A cada sincronização, o sistema registra o último NSU consultado e, nas próximas execuções, busca apenas as novas notas disponibilizadas após esse número, evitando retrabalho e downloads duplicados.

📌 Organização dos arquivos

Uma funcionalidade que achei interessante é a possibilidade de definir a estrutura das pastas automaticamente, separando por empresa, tipo de documento (Emitidas, Recebidas ou Eventos), ano e mês. Além disso, os XMLs podem ser organizados pela data de emissão e os arquivos podem ser nomeados com número da nota, nome do prestador/tomador e NSU.

📌 DANFSe e planilha para controle

Após o download dos XMLs, é possível gerar os DANFSe em PDF em lote. Os PDFs ficam salvos na mesma pasta do XML correspondente, com o mesmo nome do arquivo, facilitando a localização e conferência dos documentos.

Outro recurso bastante útil é a opção “Baixar ZIP (XML + Excel)”, que gera uma planilha contendo as informações das notas consultadas, auxiliando no controle, conferência e conciliações da rotina fiscal.

Depois de alguns dias de adaptação ao novo ambiente, a solução oficial parece estar ficando cada vez mais robusta e prática para quem trabalha diariamente com NFS-e.

🚀 Automatizando o Controle Fiscal: Integração ponta a ponta entre Qive (Arquivei) e Oracle NetSuite.

Quem trabalha com o ecossistema financeiro e fiscal sabe o desafio que é gerenciar a entrada de Notas Fiscais de Serviço eletrônicas (NFS-e). O processo manual de baixar documentos, validar dados de fornecedores e registrar tudo no ERP consome tempo precioso e abre margem para erros.

Para resolver isso, estruturei um fluxo automatizado utilizando o n8n que conecta diretamente a Qive ao Oracle NetSuite.

Como funciona a arquitetura desse fluxo:

1️⃣ Busca e Paginação Inteligente: O fluxo é ativado via agendamento (Schedule), consulta a API da Qive e utiliza um sistema de cursor estático para garantir que nenhuma nota seja duplicada ou esquecida entre os lotes.
 
2️⃣ Decodificação e Tratamento de Dados: As notas em Base64 são decodificadas e convertidas de XML para objetos JSON legíveis, extraindo dados complexos como detalhes de RPS, valores de serviços e tomadores.

3️⃣ Validação de Cadastro em Tempo Real: Antes de injetar o documento, o fluxo assina as requisições via OAuth 1.0 e consulta o NetSuite pelo CNPJ do prestador.

Se o fornecedor existe: A NFS-e é injetada automaticamente no ERP.

Se o fornecedor não existe: O time recebe um alerta imediato por e-mail com os dados do fornecedor pendente para regularização. 

4️⃣ Fechamento com Relatório Consolidado: Ao final do loop de processamento, um e-mail resumido é disparado para os responsáveis, separando o lote entre novas notas integradas, notas que já constavam no sistema (duplicadas) e eventuais erros de processamento.

Resultados práticos:

Eliminação do trabalho manual de digitação de NFS-e.

Conformidade fiscal garantida e tempo de fechamento financeiro reduzido.

Visibilidade total dos gargalos de cadastro em tempo real.

Ferramentas utilizadas: n8n, Qive API, Oracle NetSuite RESTlets (JavaScript/Crypto), Gmail API.
